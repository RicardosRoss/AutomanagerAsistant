# Nautilus 日程到 Telegram 提醒

用户画完明天的 Nautilus 日程后，计划自动同步到 VPS；每项开始时 bot 发送提醒。电脑离线不影响已同步的提醒。

## 合同

- 计划解析、弹性任务安排、容量计算全部复用 `nautilus-planner/scripts/naut.js` 和同源引擎。同步器只把数值分钟转换为带时区的日期，不重新排程。配置时区为 `Asia/Shanghai`，独立于 bot 用户统计时区。
- `add/remove/move/complete/window` 成功后，由 CLI 自动同步已启用 vault 的当天和未来日程。只读 `show` 不同步；缺失的笔记不创建。写计划成功而网络失败时明确返回 `botSync` 失败，重试只重试同步。
- 固定事件和未完成的 pinned/flex 任务均提醒。格式损坏、固定事件冲突拒绝同步；未排入时间轴的弹性任务列为排不下，不伪造开始时间。空计划是取消当天所有计划提醒。
- 日程是一次排程快照。同步之后不因时间流逝自行重排；再次编辑并同步才更新。跨午夜保留引擎数值分钟（可超过 1440），服务端按日历日期和 IANA 时区转换。
- 本地通过 SSH stdin 发送 JSON 到远程导入脚本，脚本访问本机 HTTP。接口同时检查 loopback 地址、独立 bearer secret、绑定 Telegram 用户；secret 只在 VPS 的 `.env`，不放在 Mac 或日志中。
- MongoDB 每用户每天一份快照，单文档原子替换，版本比较避免丢失并发投递状态；生成时间防止迟到的旧快照覆盖新快照。独立 Bull 队列处理开始提醒，启动、周期和 Redis 重连恢复原始开始时间。
- 每项按内容确定身份，行号不作为身份；弹性任务以唯一标题标识。同名弹性任务或同标题同时间的固定项拒绝同步，须先用标题区分。已投递的相同弹性任务再次同步不重复提醒；变动项的新随机 token 使旧队列任务和按钮失效。
- 导入时已经开始的新增项标记过期，不集中补发。已有待提醒项遇停机，只有尚未结束且迟到不超过 15 分钟时补发，并显示迟到；否则标记过期。
- 发送前原子领取并持久化状态。明确未投递的可恢复错误有限重试；超时、响应不确定和领取后进程崩溃标为投递未知，不自动重发。Telegram 与 MongoDB 没有跨系统事务，不承诺严格 exactly-once；`/schedule` 可查看状态。
- 提醒不创建 TaskChain、主链节点或预约。按钮提供“准备开始”“15 分钟内启动”“今天略过”；前两者复用 TaskDraft 确认流程，专注时长受现有约束。略过日程不破坏主链。
- 仅本人私聊可操作有效、已到开始时间且未结束的日程按钮。旧快照按钮、错误用户、完成/过期项拒绝操作。

## 验收

代码和完整 skill 均交付；真实 MongoDB、Redis 集成测试覆盖持久化、并发、重启、幂等与投递错误。通过现有全量验证后仅部署 `telegram-self-control-bot`，备份、核对数据和另一个 bot，检查健康、索引和队列。真实 Telegram 验收使用已授权私聊中的明确测试日程，不捏造用户明天的正式计划。
